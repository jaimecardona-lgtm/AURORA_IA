FastAPI · Backend
Python 3.12+ · FastAPI · Pydantic

Orquesta el negocio, verifica la identidad del usuario y envía las solicitudes a Supabase e IA sin exponer secretos.

Responsabilidades

  • Ejecutar reglas de negocio.
  • Validar las solicitudes.
Importante: cada llamada de datos debe respetar la identidad del usuario y las políticas RLS.

Flujo de punta a punta

La ruta que debe funcionar antes de generar los informes del SENA.

01
Inicio de sesiónReact inicia la sesión mediante Supabase Auth; el usuario obtiene un JWT de acceso.
02
Operaciones del negocioReact envía solicitudes HTTPS a FastAPI con el JWT; FastAPI valida el token y ejecuta los motores de calificaciones, presupuesto y tareas.
03
Persistencia privadaFastAPI accede a Supabase bajo el contexto del usuario; PostgreSQL aplica RLS para que cada persona opere solo sobre sus datos.
04
Copiloto inteligenteFastAPI resume datos permitidos y consulta OpenRouter con la clave privada del servidor. El modelo responde sin alterar registros automáticamente.
05
DespliegueGitHub activa la compilación Docker en Render; un servicio FastAPI publica la API y sirve la aplicación React compilada.

Decisiones de ingeniería

Alcance que usaremos para el primer prompt.

ArquitecturaMonorepo con frontend/, backend/, supabase/migrations/ y docs/.
SeguridadJWT validado en FastAPI, acceso por usuario y RLS con comprobaciones de permisos; nunca usar una clave secreta de Supabase en React.
DespliegueUna Web Service Docker en Render para reducir infraestructura y mantener React + API en el mismo origen.
DominioCalificaciones, presupuesto en COP y tareas reutilizan las reglas Python de la actividad previa.
AprendizajePrimero arquitectura y código verificado; después pruebas reales, capturas, informe AA2-EV01 y video AA2-EV02.
Estado inicial: existe un repositorio prototipo con React/FastAPI y lógica local; Supabase Auth, PostgreSQL y las pruebas de despliegue son objetivos por implementar, no resultados ya alcanzados.
